## Hedef

`.github/workflows/ci.yml:84` `npx tsc --noEmit` koşuyor ve bu komut bu repoda
**exit 0 döndürüp hiçbir dosyayı denetlemiyor** (solution-style tsconfig; G026'nın
bulgusu, bu gecenin keşfinde yeniden doğrulandı). Yani CI'ın "TypeScript kontrolü"
adımı bugün **boş bir kapı** — yeşil olması hiçbir şey kanıtlamıyor.

Bu, FAZ B'nin (emniyet ağı) tam merkezindeki bir kusur: plan §4 "CI 5/5 yeşil" diyor,
ama beşten biri sahte. Kapıyı gerçeğe çevir.

**Sıra kritik:** G036 dört tip hatasını kapatmadan bu görev koşarsa CI kırmızıya düşer.
`bagimli:G036` bu yüzden.

## Rapor

### Yapılanlar

1. **`.github/workflows/ci.yml` "TypeScript kontrolü" adımı:**
   `npx tsc --noEmit` → **`npx tsc -b --force`** (job `working-directory: frontend`).
   Adımın üstüne, kapının neden çıplak biçimde sahte olduğunu ve `-b`/`--force`
   seçimlerinin gerekçesini anlatan yorum bloğu eklendi.
2. **`gorevler/README.md`:** görev şablonunun "Doğrulama" örneğine frontend lint +
   gerçek tip denetimi komutu eklendi; ayrıca **"Frontend tip denetimi: çıplak
   `tsc --noEmit` YAZMA"** başlıklı kalıcı uyarı bölümü yazıldı (yeni görevler sahte
   kapıyı miras almasın).

### Alınan kararlar + gerekçeleri

- **`-p tsconfig.app.json` yerine `-b --force` seçildi.** Kabul kriteri ikisine de izin
  veriyordu; `-b` kök `tsconfig.json`'ın `references`'ını gerçekten izlediği için tek
  komutla **iki projeyi de** kapsıyor. `--verbose` ile kanıtlandı:
  ```
  Project 'tsconfig.app.json' is being forcibly rebuilt
  Project 'tsconfig.node.json' is being forcibly rebuilt
  ```
  Yani ikinci kabul kriteri (`tsconfig.node.json` kapsanıyor mu) **kapsanıyor** yanıtıyla
  kapandı — gerekçe yazmaya gerek kalmadı. `-p` biçimi seçilseydi `vite.config.ts`
  denetimsiz kalacaktı.
- **`--force` bilinçli.** Build modu inkremental "up to date" atlaması yapabilir;
  `--force` niyeti komutun kendisinde açık tutar (temiz CI checkout'unda zaten etkisiz).
  Bu konfigürasyonda `.tsbuildinfo` üretilmiyor (her iki projede `noEmit: true`;
  koşu sonrası `git status` temizdi) — kirlilik riski yok.
- **`npm run build` tip kapısı DEĞİL.** `frontend/package.json` `build` script'i düz
  `vite build` (esbuild = transpile-only). Yani tip denetimi tek noktada duruyor; bu
  yüzden o adımın gerçek olması kritik. (`package.json` kapsam dışı, dokunulmadı.)

### Kapının gerçekten kırıldığının kanıtı (3. kabul kriteri)

`frontend/src/__tsc_gate_probe.ts` geçici dosyası yazıldı:
`export const probe: number = "bu bir string, number degil";`

| Komut | Sonuç (probe DURURKEN) |
| --- | --- |
| `npx tsc --noEmit` (eski, çıplak) | **exit 0, çıktı yok** — hatayı GÖRMEDİ ⇒ sahte kapı doğrulandı |
| `npx tsc -b --force` (yeni CI komutu, cwd=`frontend`) | **sıfırdan farklı çıkış**, `src/__tsc_gate_probe.ts(2,14): error TS2322: Type 'string' is not assignable to type 'number'.` |
| `npx tsc --noEmit -p tsconfig.app.json` | sıfırdan farklı çıkış, aynı TS2322 satırı |

Probe silindikten sonra `npx tsc -b --force` **temiz/exit 0**; `git status` temiz
(artık dosya bırakmadı). "Yeşil geçti" tek başına delil sayılmadı — kırmızıya
düşürülüp geri alındı.
