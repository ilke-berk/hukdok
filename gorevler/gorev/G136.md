## Hedef

Sıfır-context bir oturumun raporlama modülünü koddan doğrulanmış tek dokümandan anlaması. ALTIN KURAL:
her uç adı, env, tablo adı, limit **koddan okunarak** yazılır (`routes/reports.py`, `schemas_rapor.py`,
`services/rapor/*`, `models.py`, `services/app_settings.py`, `config/settings.py`); plan dosyasındaki
sözleşme ile kod çelişiyorsa kod haklıdır — plan §2'ye "uygulamada değişti" şerhi düşülür.

## Yapılacaklar

1. **`docs/mimari/raporlama.md`:** amaç ve kapsam (yalnız yönetici, test aşaması); akış şeması (oluşturucu →
   `/preview` → `/export` → `report_runs` + dosya saklama → `/runs`; asistan → `/chat` → tanım → aynı export
   yolu); kayıt defteri (veri kaynakları, kolon tipleri, op tablosu — koddan); güvenlik modeli (serbest SQL yok,
   LLM tanımı yeniden doğrulanır, tenant/soft-delete, path traversal, CSV enjeksiyon); tablolar; env'ler ve
   varsayılanları; admin anahtarı; log sözleşmesi; bilinen sınırlar (v1 kapsam dışı listesi plan §1'den);
   işletme notları (saklama dizini volume'da, temizlik tembel, RSS ölçümü G131 raporundan).

   doküman haritasına `docs/mimari/raporlama.md` satırı; kritik tuzaklara gerekiyorsa tek madde
   (ör. "asistan tanımı doğrulanmadan kullanılmaz").
3. **Plan dosyası:** başlığa durum + hangi kabul kriterinin nasıl kanıtlandığı (G130-G135 raporlarından
   test dosyası adları).

   dokunabilir — kod değil).
