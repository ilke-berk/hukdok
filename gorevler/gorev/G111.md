## Hedef

Plan §2. Yöneticinin teslim defterini görebildiği, dosya yükleyebildiği, tarama tetikleyip
kuru koşu raporlarını indirebildiği ve `inceleme_bekliyor` teslimi bilinçli onayla
uygulayabildiği tek ekran. Backend bandıyla PARALEL koşar: API sözleşmesi G108'de DONDURULDU
ve aşağıya kopyalandı; frontend bu sözleşmeye göre yazılır, backend gelince değişiklik
gerekmemeli.

## SÖZLEŞME (G108 ile birebir — sapma gerekiyorsa BLOKE bırak)

- `GET /api/admin/aktarim/teslimler?limit=50` → `{ teslimler: Teslim[], esikler: { hata_orani, eslesmeyen_orani, alan_degisikligi }, etkin: boolean }`
- `GET /api/admin/aktarim/teslimler/{id}` → `Teslim` (+ `durum_gecmisi: {durum, at, not}[]`)
- `POST /api/admin/aktarim/teslimler` multipart `file` → `201 { id, durum }`; 400 uzantı hatası
- `POST /api/admin/aktarim/teslimler/{id}/kuru-kos` → `{ id, durum, kapi_karari, kapi_gerekcesi }`; 409 uygun olmayan durum
- `POST /api/admin/aktarim/teslimler/{id}/uygula` gövde `{ onay: true }` → `{ id, durum }`; 409
- `GET /api/admin/aktarim/teslimler/{id}/raporlar` → `{ dosyalar: { ad, boyut }[] }`
- `GET /api/admin/aktarim/teslimler/{id}/raporlar/{ad}` → dosya (blob)
- `POST /api/admin/aktarim/tara` → `{ yeni, yinelenen, not? }`

`Teslim`: `id, dosya_adi, sha256, kaynak: "sharepoint"|"yukleme", durum, onceki_teslim_adi,
zincir_tamam, okunan, islenen, atlanan, hata_sayisi, alan_degisikligi, kart_degisen,
envanter_denk, kapi_karari: "otomatik"|"inceleme"|null, kapi_gerekcesi, cevap_yuklendi,
uygulayan, hata_mesaji, created_at, updated_at, done_at` (sayısal/boolean alanlar `null` olabilir).

Durumlar: `alindi · yinelenen · reddedildi · dogrulandi · kuru_kosuldu · inceleme_bekliyor ·
uygulaniyor · uygulandi · basarisiz`.

## Tasarım

- `AdminPage` sekmesi `value="deliveries"`, etiket "Veri Teslimleri", "Özellikler"in yanına.
  Mevcut trigger sınıfları birebir kopyalanır.
- Kart üstü: "Şimdi tara" (POST tara; sonuç toast: "N yeni, M yinelenen"; `not` varsa onu
  göster), "Dosya yükle" (`<input type="file" accept=".xlsx">`; 201'de liste yenilenir),
  sağda `etkin=false` ise sarı uyarı satırı: "Otomasyon kapalı — Özellikler sekmesinden açın".
- Tablo: dosya adı · kaynak · durum rozeti (renk: `uygulandi` yeşil, `inceleme_bekliyor` amber,
  `basarisiz`/`reddedildi` kırmızı, diğerleri nötr) · okunan/işlenen/atlanan/hata · alan
  değişikliği · kapı (karar + gerekçe tooltip) · tarih (`tr-TR`).
- Satır aksiyonları: "Kuru koş" (izinli durumlarda), "Raporlar" (liste açılır, her satır
  indirme — `apiClient.fetch` ile blob alınıp `URL.createObjectURL`), "Uygula" yalnız
  `inceleme_bekliyor`/`kuru_kosuldu`da; tıklanınca onay diyaloğu: dosya adı + sayaçlar + kapı
  gerekçesi + mesai saatindeyse (09:00–18:00 TR, yerel saatten) ek uyarı satırı; onayda
  `{ onay: true }`.
- Hata yolları: 409 → toast "Bu durumda uygulanamaz"; 400 → sunucu `detail`'i; ağ hatası →
  genel toast. `apiClient.fetch` istisna fırlatmaz, `Response.ok` kontrol edilir.
- Sayfa tam genişlik kuralı (bellek notu: redesign sayfaları max-w cap kullanmaz).

- **"Kuru koş" izinli durumlar** sözleşmede sayılmamış; kart `alindi · dogrulandi ·

- **Kapı gerekçesi tooltip'i** Radix Tooltip yerine native `title` attribute'u:
  provider gerektirmez, jsdom'da doğrudan sorgulanır, sekmede başka tooltip yok.
- **Hata metni**: 400/500'de sunucu `detail` string'i varsa o, yoksa sabit yedek
