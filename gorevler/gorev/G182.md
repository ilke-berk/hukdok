# G182 — Route düzeyinde kod bölme (React.lazy) + sonner statik import + nginx asset önbelleği

- **Bant:** frontend
- **Bağımlı:** -
- **Dosya kapsamı:** `frontend/src/App.tsx`, `frontend/src/lib/api.ts` (yalnız `import("sonner")` satırı), `frontend/vite.config.ts` (gerekirse), `nginx.conf`, yeni test `frontend/src/App.lazy.test.tsx`
- **Dokunma:** `frontend/src/pages/**` içerikleri (yalnız import edilme biçimi değişir, sayfa kodu değişmez), `frontend/src/components/ProtectedAdminRoute*`, `frontend/index.html`

Kaynak: `docs/arsiv/performans-denetimi-2026-09-14.md` F1, F2, F12, F14.

## Hedef
Tüm uygulama tek 1.529 kB (gzip 422 kB) JS parçasında; giriş sayfası bile hepsini indiriyor
ve lokalde DOMContentLoaded 1,3 sn'nin neredeyse tamamı JS çözümleme. 14 sayfanın hepsi
`App.tsx:18-33`'te statik import. Sayfaları `React.lazy` + `Suspense` ile route başına parçaya
ayır; yalnız admin'in açtığı `/reports` + `/admin` (rapor katmanı 128 kB + admin 74 kB +
`@dnd-kit` 45 kB) admin olmayan kullanıcıya hiç inmesin. Hash'li asset'lere `Cache-Control`
başlığı ekle (şu an yok: her açılışta yeniden doğrulama).

## Kabul kriterleri
- [ ] `App.tsx`'te `Login` ve `NotFound` dışındaki tüm sayfalar `React.lazy(() => import(...))` ile yüklenir; `Routes` tek bir `Suspense` ile sarılıdır, fallback mevcut tasarım diline uygun küçük bir yükleniyor göstergesidir (yeni bağımlılık YOK).
- [ ] Deploy sonrası bayat parça sorunu ele alınmıştır: eski `index.html`'in referans verdiği hash'li parça 404/`ChunkLoadError` verdiğinde uygulama BİR kez `location.reload()` yapar (sessionStorage bayrağıyla döngü engellenir); bu davranışın birim testi vardır.
- [ ] `import("sonner")` dinamik import'ları (`App.tsx:182`, `lib/api.ts:134`) statik import'a çevrilmiştir (24 dosyada zaten statik; Vite uyarısı kalkar). Davranış aynıdır: toast çağrıları değişmez.
- [ ] `npm --prefix frontend run build` çıktısında: en az 8 JS parçası vardır; giriş parçası (`index-*.js`) gzip ≤ 300 kB; `ReportsPage`/`AdminPage`/`dnd-kit` kodu giriş parçasında DEĞİLDİR (build çıktısındaki parça listesi rapora yapıştırılır, `grep -c "dnd" dist/assets/index-*.js` = 0).
- [ ] `nginx.conf`'a `location ~* ^/assets/` bloğu eklenmiştir: `Cache-Control "public, max-age=31536000, immutable"`; `index.html` için `Cache-Control "no-cache"` (SPA `try_files` bloğunda). Mevcut güvenlik `add_header`'ları (`nginx.conf:41` civarı) yeni `location` bloğunda YİTİRİLMEZ (nginx `add_header` kalıtım kuralı: alt blokta bir `add_header` varsa üsttekiler düşer — hepsini tekrar yaz ya da `include` ile ortaklaştır). `docker compose build frontend && docker compose up -d frontend` sonrası `curl -sI http://localhost:8080/assets/<parça>.js` ve `curl -sI http://localhost:8080/` çıktıları rapora.
- [ ] `nginx.conf` başındaki yorum bloğu (gzip gerekçesi gibi) yeni önbellek kararını ve host nginx'in aynı başlığı ekleyip eklemediğinin prod'da doğrulanacağını not eder.
- [ ] Mevcut tüm vitest testleri yeşil; `AdminPage.test.tsx` ve `ReportsPage.*.test.tsx` sayfaları doğrudan import ettiği için etkilenmez (doğrula).
- [ ] Sayfa kodlarına (`pages/**`) dokunulmamıştır (`git diff --stat`).
