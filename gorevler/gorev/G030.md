# G030 — B.1: pytest-cov + CI kapsam kapısı

- **Bant:** backend
- **Bağımlı:** -
- **Dosya kapsamı:** backend/requirements-dev.txt, backend/pyproject.toml, .github/workflows/ci.yml
- **Dokunma:** backend/tests/conftest.py (DOKUNMA — G031/G033 orada çalışacak), backend/requirements.txt (prod imajı; dev aracı BURAYA GİRMEZ)

## Hedef

Kapsam ölçümü bugün klondan tekrar üretilemiyor: `requirements-dev.txt` içinde
`pytest-cov` YOK (doğrulandı — dosyada yalnız pytest/httpx/ruff/mypy var). Plan §4'ün
"%58,5 uygulama kapsamı" rakamı bu yüzden doğrulanamaz bir iddia.

`pytest-cov`'u dev bağımlılıklarına ekle, CI'da `--cov` koştur ve **mütevazı** bir
`--cov-fail-under` eşiği kur. Eşik bir hedef değil, **gerilemeyi yakalayan taban**dır.

## Kabul kriterleri

- [x] `backend/requirements-dev.txt`'e `pytest-cov` sabit sürümle eklendi (`==`), prod
      `requirements.txt`'e DOKUNULMADI
- [x] Kapsam **önce ölçüldü**, gerçek rakam görev raporuna yazıldı; `--cov-fail-under`
      ölçülen değerin **2 puan altına** kuruldu (tahmin YASAK — ölçülen sayı rapora girer)
- [x] Kapsam yalnız uygulama kodunu sayar: `--cov=.` ile birlikte `tests/` ve `scripts/`
      dışlandı (`.coveragerc` ya da `pyproject.toml` `[tool.coverage.run] omit`)

      GİRMEZ (lokal koşuyu yavaşlatır); yalnız CI adımına eklenir
- [x] `.github/workflows/ci.yml` backend job'unda pytest adımı `--cov --cov-fail-under=N`
      ile koşuyor; N görev dosyasında gerekçeli yazılı
- [x] Dev araçları kurulu olmayan bir konteynerde `python -m pytest` hâlâ çalışıyor

## Doğrulama

- `docker compose exec -T backend pip install -r requirements-dev.txt`
- `docker compose exec -T backend python -m pytest`

- `docker compose exec -T backend python -m ruff check .`
- `docker compose exec -T backend python -m mypy`

## Rapor

### Yapılanlar

1. `backend/requirements-dev.txt`: `pytest-cov==7.1.0` eklendi (pip'in python:3.10-slim
   üzerinde çözdüğü sürüm; `coverage==7.15.4` geçişli bağımlılık olarak gelir). Prod
   `backend/requirements.txt` DOKUNULMADI — dev aracı prod imajına girmez.
2. `backend/pyproject.toml`: `[tool.coverage.run] omit = ["tests/*", "scripts/*"]`
   bölümü eklendi. `[tool.pytest.ini_options] addopts = "-q"` **aynen korundu**; üstüne
   `--cov`'un neden addopts'a yazılmadığını anlatan yorum eklendi.
3. `.github/workflows/ci.yml`: backend job'undaki `pytest` adımı
   `pytest --cov=. --cov-report=term-missing:skip-covered --cov-fail-under=58` oldu,
   adı `pytest (kapsam kapısı)`. Ölçülen değer ve eşiğin gerekçesi adımın üstüne yorum
   olarak yazıldı. Mevcut `cache-dependency-path` zaten `requirements-dev.txt`'i
   kapsadığı için pip cache anahtarı kendiliğinden yenilenir — ek değişiklik gerekmedi.

### Ölçüm (tahmin değil — koşuldu)

`docker compose exec -T backend python -m pytest --cov=. --cov-report=term-missing`
(imaj yeniden kuruldu; backend bind-mount etmediği için pyproject değişikliği ancak
rebuild'le konteynere iner):

```
TOTAL                                     12076   4827  60.03%
975 passed, 2 skipped
```

- Ölçülen uygulama kapsamı: **%60,03** (12.076 ifade, 4.827'si kapsanmamış).
- Sayılan dosya: **83** uygulama modülü. `tests/` ve `scripts/` raporda **0 satır** —
  omit çalışıyor (`coverage report | grep -Ec "^(tests|scripts)/"` → 0).
- **Eşik: `--cov-fail-under=58`** = ölçülenin 2 puan altı. Gerekçe: eşik bir hedef
  değil, gerilemeyi yakalayan taban; 2 puanlık pay CI ile lokal konteyner arasındaki
  ortam farkının (platforma bağlı dallar) yanlış kırmızı üretmesini önler.
- CI komutunun birebir aynısı konteynerde koşuldu:
  `Required test coverage of 58% reached. Total coverage: 60.04%` → kapı GEÇTİ.
  (İki koşu arasındaki 60,03 ↔ 60,04 oynaması `skip-covered` raporlamasından değil,
  ölçüm gürültüsünden; eşik payı bunu da kapsıyor.)

### Kritik kriter #6 — dev araçsız konteynerde pytest

Rebuild sonrası konteynerde hiçbir dev aracı yokken (`pip list | grep -Ei
"pytest|coverage|ruff|mypy"` → boş), yalnız `pytest==8.3.5 httpx==0.28.1` kurulup
(pytest-cov **kurulmadan**) `python -m pytest` koşuldu:

```
975 passed, 2 skipped, 2 warnings in 31.29s
```

`--cov` addopts'ta olmadığı için pytest-cov'suz ortam kırılmıyor. Bu, prod imajında
teşhis amaçlı pytest kurulumunun çalışmaya devam etmesi demek.
