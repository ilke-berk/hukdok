## Hedef

G163 raporundaki NOT (kullanıcı kararı 10.09: görev açıldı). Eski küçültme `str.lower()` "İ"yi "i" + U+0307
(COMBINING DOT ABOVE) yapıyordu; bu kalıntı ekranda "Si̇gorta", "Hi̇zmetleri̇" gibi çift noktalı görünüyor, aramayı ve
ikiz tespitini bozuyor (anahtar U+0307'yi görür → "Axa Si̇gorta A.Ş." ile "Axa Sigorta A.Ş." ikiz sayılmaz).
Lokal ölçüm (10.09, apply sonrası DB): **`case_parties.name` 6.422 satır / 4.403 tekil ad**; korunan rollerde (Sigortalı,
Davalı İdare) 0; `cases.court` 1 satır ("İstanbul 3. Bölge İdare Mahkemesi̇"); `clients.name`, `cases.subject/sub_type/
responsible_lawyer_name/dosya_son_durumu`, `case_documents.muvekkil_adi`, `case_stage_decisions.mahkeme/aciklama`,
`case_foys.ham_veri` → 0. U+0307'nin önündeki karakter 9.063 kez "i", 2 kez "İ" ("İ̇stanbul", "İbn-İ̇").
Temiz hedefi DB'de ZATEN olan 126 tekil ad var (390 satır; ör. "Axa Si̇gorta A.Ş." 34 → "Axa Sigorta A.Ş." 3.789) —
temizlik sonrası aynı string'e düşerler, ikiz kalmaz.

**Kapsam DIŞI (bilerek):** "Sağlik" / "Hi̇z." gibi ı→i harf bozuklukları (U+0307 içermeyen, ASCII lower kalıntısı) —
sözlüksüz düzeltilemez, dokunulmaz; "Dr"/"Dr." ve "A.Ş"/"AŞ" biçimleri (G163/G164 kuralları).

## Yapılacaklar

1. **Adım 0 — `adim_0_combining_dot(db)`** (`kos` içinde adım 1'den ÖNCE koşar; `--adim 0` tek başına da koşabilir):
   `case_parties.name` (`_taraf_satirlari`, korunan roller dışarıda) + `cases.court` (silinmemiş kartlar) için
   `hedef = temizle(deger)`; `hedef != deger` ise `Degisiklik(kaynak="nfc")`. Diğer kolonlar ölçümde 0 → kapsama alınmaz
   (rapora "0 olduğu için" notu).
2. **`temizle(s)`:** `unicodedata.normalize("NFC", s)` → `"i̇" → "i"` → `"İ̇" → "İ"` → kalan tekil U+0307
   varsa (öncesi i/İ değilse) **dokunma** ve raporda listele (beklenen 0). Başka hiçbir karakter değişmez (büyük/küçük,
   nokta, boşluk aynen). Saf fonksiyon, test edilir.
3. **Sıra gerekçesi:** temizlik önce koşar ki adım 2/2b/3 anahtarları temiz metni görsün; aynı koşuda adım 2'de yeni açığa
   çıkan ikizler (büyük/küçük farkı kalanlar) normal kuralla çözülür. Kuru koşu çıktısında adım 0 sonrası adım 2/2b
   sayıları AYRICA raporlanır (adım 0 uygulanmış gibi hesaplanır: bellek içi hedef sözlüğü ya da "adım 0 sonrası" ikinci
   hesap — koşucu seçer, gerekçeli).
4. **CLI:** adım 0 özet satırı + `0.csv`; kuru koşuda ilk 15 tekil (satır sayısına göre). `--apply` yolu aynı `_uygula`
   (tarihçeli `case_history`, `--kim` zorunlu; `cases.court` için kart alanı tarihçesi `court`).
5. **Test:** (a) `temizle` saf kural: "Si̇gorta"→"Sigorta", "İ̇stanbul"→"İstanbul", U+0307'siz metin aynen, NFD girdi NFC'ye,
   "Sağlik" DEĞİŞMEZ; (b) adım 0 taraf + court değişikliği, korunan rol değişmez, silinmiş kart yok; (c) temiz hedefi
   zaten var olan ad → aynı string, satır SİLİNMEZ (iki satır aynı adla kalır, `case_party_id` sabit); (d) `kos` sırası
   0 → 1 → …; (e) apply + tarihçe + envanter denk + ikinci koşu 0.
6. **README + plan §6e** tek cümle.
