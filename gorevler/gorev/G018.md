# G018 — Altyapı: gzip, eksik preview proxy'si, init:true, backend/.dockerignore

- **Bant:** backend *(altyapı dosyaları backend bandı sayılır — doğrulaması ayakta stack ister)*
- **Bağımlı:** -
- **Dosya kapsamı:** nginx.conf, docker-compose.yml, backend/.dockerignore (YENİ), frontend/vite.config.ts (yalnız dev proxy allowlist'i)
- **Dokunma:** docker-compose.override.yml.example, infra/**, frontend/src/** (vite.config.ts DIŞINDA hiçbir frontend kaynağına dokunma — vitest bu değişiklikten etkilenmez)

## Hedef

Plan FAZ A.1 + A.3 + 0.7 + A.2'nin otomatiklenebilir kısmı. Dört küçük, davranışsız
(ya da açıkça arıza düzelten) altyapı düzeltmesi:

**1. gzip kapalı (A.1).** `nginx.conf`'ta `gzip` geçen tek satır yok. Ölçüldü: JS chunk'ı
**1.324.033 bayt** ham, gzip'li karşılığı **361.003 bayt**. `curl -H 'Accept-Encoding: gzip'`
yanıtında `Content-Encoding` başlığı yok. Repo genelinde (`*.md`, `*.conf`, `*.yml`) gzip'ten
söz eden tek satır bulunamadı — yani başka katmanda bilinçli yapıldığına dair kanıt da yok.

**2. `/preview-client-email-body` proxy'lenmiyor (0.7).** `nginx.conf` location listesi:
`/`, `= /healthz`, `/api`, `/process`, `/confirm`, `/preview-email-body`, `/refresh`.
Müvekkil olanı **yok** → müvekkil bilgilendirme AI metni sessizce yanlış tonlu frontend
fallback'ine düşüyor. `frontend/vite.config.ts` dev proxy'sinde **ikisi de yok**, yani
`npm run dev` ile çalışan geliştirici avukat önizlemesinin de düştüğünü görür.
Aynı allowlist üç yerde elle tutuluyor (nginx.conf, vite.config.ts, `frontend/src/lib/api.ts`
`LONG_TIMEOUT_PREFIXES`) ve üçü de birbirinden sapmış — bu görevde **senkronize edilir**,
yeniden tasarlanmaz (route'ları `/api` altına toplama önerisi kapsam dışı).

**3. `init: true` yok (A.3).** Her soffice dönüşümü 5 zombie süreç bırakıyor (ölçüldü:
212 → 230 = 42 dönüşüm × 5); konteynerde reaper yok. `docker-compose.yml`'de backend
servisine `init: true` eklenmeli.

**4. `backend/.dockerignore` yok (A.2 kısmi).** Kökte `.dockerignore` var (92 bayt) ama
backend build context'i `./backend` (`docker-compose.yml:38`) olduğu için **uygulanmıyor**.
İmajdaki `/app` 329 MB: 134 MB legacy SQLite + 139 MB calibration + 29 MB `.mypy_cache` +
2,7 MB `tests`. Bu görev **yalnız `.dockerignore` dosyasını yazar**.

> **KAPSAM DIŞI — kullanıcı işi.** `backend/data/hukudok.db` (140 MB gerçek müvekkil verisi)
> ve `backend/calibration/` (139 MB gerçek müvekkil PDF'i) **bu görevde SİLİNMEZ/TAŞINMAZ**.
> Gerçek müvekkil verisidir, OneDrive senkronu altındadır ve silme/taşıma kararı kullanıcıya
> aittir (plan A.2). Otomasyon oturumu kullanıcı verisi silmez.

> **KAPSAM DIŞI — deploy.** Bu görev `docker compose up -d` KOŞMAZ. Değişiklikler config
> doğrulamasıyla sınanır; canlıya alınması deploy kararıdır (kullanıcıda).

## Rapor

**DURUM: TAMAM**

### Yapılanlar

**1. gzip açıldı (`nginx.conf`, server bloğu).** `gzip on` + `gzip_vary on` +
`gzip_comp_level 5` + `gzip_min_length 1024` + `gzip_proxied any`, ve `gzip_types`
listesi: `text/plain, text/css, text/xml, text/javascript, application/javascript,
application/json, application/xml, application/manifest+json, image/svg+xml`.
Zaten sıkıştırılmış tipler (jpg/png/pdf/woff2) bilerek DIŞARIDA; `text/html` de
listeye yazılmadı — nginx onu varsayılan olarak zaten sıkıştırır, yazılırsa
"duplicate MIME type" uyarısı üretir.

**2. `/preview-client-email-body` proxy'si eklendi (`nginx.conf`).**
`/preview-email-body` ile birebir aynı `proxy_pass`/başlık seti; server-düzeyi
`proxy_read_timeout 300s` ikisini de kapsıyor. nginx prefix eşleşmesi olduğu için
mevcut `/preview-email-body` location'ı bu yolu YAKALAMIYORDU — istek `location /`
try_files'ına düşüp `index.html` dönüyordu (frontend'in sessiz fallback'inin sebebi).
Backend ucu doğrulandı: `routes/processing.py:347`.

**3. `init: true` eklendi (`docker-compose.yml`, backend servisi).** Merge edilmiş
konfigde doğrulandı (`docker compose config` → `init: true`).

**4. `backend/.dockerignore` yazıldı (YENİ).** Dışlananlar: `data/`, `calibration/`,
`.mypy_cache/`, `.pytest_cache/`, `.ruff_cache/`, `.coverage`, `**/__pycache__`,
`**/*.py[cod]`, `tests/`, `.env`, `.env.*`, `*.log`, `REFACTOR_PLAN.md`.

### Bulunan allowlist sapmaları (üç yerin senkronu)

Referans (en eksiksiz) liste `frontend/src/lib/api.ts::LONG_TIMEOUT_PREFIXES` idi;
**her iki preview ucunu da zaten içeriyordu** (`api.ts:68-69`) → o dosyada
değişiklik GEREKMEDİ, "Dokunma" listesindeki `frontend/src/**` hiç açılmadı.

| Uç | nginx.conf (önce) | vite.config.ts (önce) | api.ts |
| --- | --- | --- | --- |
| `/preview-email-body` | VAR | **YOK** → eklendi | VAR |
| `/preview-client-email-body` | **YOK** → eklendi | **YOK** → eklendi | VAR |

`/healthz` bilinçli olarak vite dev proxy'sine EKLENMEDİ: `frontend/src` altında
"healthz" geçen tek satır yok (grep, 0 eşleşme) — SPA bu ucu hiç çağırmıyor, izleme
(GCP uptime check) ucudur. Dev proxy'yi yalnız uygulamanın çağırdığı yollarla sınırlı
tuttum.

### `.dockerignore` — Dockerfile'a karşı doğrulama

`backend/Dockerfile` satır satır okundu; dışlananların hiçbiri build'de gerekmiyor:

- **`fonts/`** dışlanMADI — DejaVu TTF'leri repodan geliyor (apt'ın kurduğu
  `fonts-dejavu-core` ayrı); imajda duruyor (aşağıdaki `ls` kanıtı).
- **`requirements-dev.txt`** bilinçli olarak dışlanMADI — CLAUDE.md'deki
  `docker compose exec -T backend pip install -r requirements-dev.txt` adımı
  konteynerin İÇİNDE koşuyor, dosya imajda kalmalı.
- **`data/`** güvenli: `Dockerfile:37` `mkdir -p /app/data` ile dizini yaratıyor,
  prod'da üstüne `backend-data` named volume biniyor. İçindekiler runtime'da
  üretiliyor (`process_cache`, `conversion_spool`, `upload_spool`).
  `managers/config_manager.py:92` mojibake haritasını `managers/data/` altında arıyor
  (`backend/data/` DEĞİL) ve o dizin zaten yok — davranış değişmiyor.
  `vault.py:24` ise `~/AppData/Local/HukuDok/data`'ya bakıyor, imajla ilgisi yok.
- **`calibration/`** güvenli: içindeki araçlar (`run_calibration.py`, `smoke_faz*.py`)
  ve AVG TLS çözümündeki `ca_bundle.pem` yalnız lokalde,
  `docker-compose.override.yml`'in `./backend:/app` bind-mount'u üzerinden kullanılıyor
  — imajdaki kopya hiç okunmuyor.
- **`test_yetki.udf`** (kök seviyesi fixture) dışlanMADI; `tests/` deseni onu tutmuyor.

**`tests/` dışlamasının sonucu (izlenecek):** lokalde konteyner testi zaten
`docker-compose.override.yml`'in `./backend:/app` mount'u üzerinden HOST'taki
`tests/` dizinini koşuyor (mevcut konteynerde `docker inspect` ile doğrulandı) —
bu koşu etkilenmiyor. Ancak **override'ı OLMAYAN** bir ortamda (temiz makine, prod)
`docker compose exec backend python -m pytest` artık test dosyası bulamayacak.
Bu, `.dockerignore` dosyasının içine yorum olarak da yazıldı.
