## Hedef
Gerçek geçiş insan adımıdır (dump/restore, mesai dışı). Bu görev onu RİSKSİZ hale getirir: lokal DB'nin kopyasını
geçici bir PG17 konteynerine taşır, şemanın, migrasyonların, test paketinin ve arama planlarının 17'de aynı
çalıştığını ölçer, ölçülmüş süre ve komutlarla runbook yazar.

**2. Geçici konteyner:** `docker run -d --name hukdok_pg17_prova` · `postgres:17-alpine` (17.11) · ayrı hacim
`hukdok_pg17_prova_data` · port yayını YOK (yalnız compose ağı `hukudok-automator-main_hukudok-network`'e bağlı,

**3. pg_restore (PG17 istemcisi):** **3,04 sn, 549 TOC kalemi, 0 hata / 0 uyarı** (çıktı boş). İlk iki deneme DB'ye
dokunmadan düştü (geçersiz `--exit-on-error=0` sözdizimi; Git Bash `/tmp` yol çevirisi → `MSYS_NO_PATHCONV=1`).
Sayım 15 ↔ 17: tablo 60=60, index (`pg_indexes` public, `\di` eşdeğeri) 173=173, `gin_trgm_ops` 11=11

139 MB → 69 MB (restore şişmeyi atar).

**4. migrate.py PG17'ye:** `docker compose exec -T -e DATABASE_URL=postgresql://…@hukdok_pg17_prova:5432/hukudok
backend sh -c 'python -c <hedef yazdır> && python migrate.py'` → rc=0, **1,95 sn**. Ana DB'ye bağlanılmadığı
kanıtı: aynı süreçte önce `HEDEF: PostgreSQL 17.11 … 172.18.0.5 17.11` basıldı (ana DB 15.15, farklı IP); log
`Tables created/verified` → `Trigram index'leri hazır` → `pg_stat_statements hazır` → `Database ready`.
İdempotent: migrate sonrası PG17 şema dump'ı ile ana PG15 şema dump'ı `diff` → BOŞ (yalnız `\restrict` anahtarı,
17'nin `SET transaction_timeout` satırı ve `ALTER TABLE/SEQUENCE … OWNER` yazım farkı ayıklanarak) → yeni op yok.

**5. Tam pytest PG17'ye:** conftest DB'yi `DATABASE_URL`'den (setdefault) ve `dbtest` testleri
