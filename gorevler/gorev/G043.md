# G043 — D 6.2-b: eksik index'leri ekle + E7 avukat filtresi

- **Bant:** backend
- **Bağımlı:** G042
- **Dosya kapsamı:** backend/database.py, backend/managers/case_manager.py, backend/tests/
- **Dokunma:** backend/models.py (DOKUNMA)

## Hedef

6.2'nin ekleme yarısı. G042 düşürüyor, bu görev ekliyor; net etki yazma yolunu
**ucuzlatmak** (plan: net −23 index).

Ayrıca **FAZ E'nin E7 maddesi** buraya bağlı: avukat filtresi bugün iki `.all()` + Python
ile çalışıyor (`case_manager.py:73-87`, ölçüm 116 ms, doğrusal büyüyor) ve doğru çözümü
index + SQL filtresi — yani D'nin index işi olmadan yapılamaz. Bu yüzden E'den D'ye taşındı.

## Kabul kriterleri

- [ ] Index'siz FK kolonlarına index eklendi. **Liste tahminle değil sorguyla üretilir:**
      `pg_constraint contype='f'` ∩ index'i olmayan kolonlar. Bulunan liste rapora yazılır
      (plan "4 kolon" diyor — doğrula, sayı farklıysa gerçeği yaz)
- [ ] `cases.status` için **kısmi** index (yalnız sıcak durum değerleri; hangi değerlerin
      sıcak olduğu `SELECT status, count(*) FROM cases GROUP BY 1` ile belirlenir)
- [ ] `substr(tracking_no,4,10)` için **fonksiyonel** index — `routes/cases.py:139`
      her dava açma formunda bu ifadeyi kullanıyor. Index'in gerçekten kullanıldığı
      `EXPLAIN` çıktısıyla kanıtlandı (plan yazıp geçme, planı GÖSTER)
- [ ] **E7:** avukat filtresi iki `.all()` + Python yerine SQL filtresine taşındı;
      davranış eşdeğerliği kanıtlandı — en az 10 avukat için eski/yeni id kümesi
      **birebir aynı**; önce/sonra süre ölçüldü
- [ ] Her yeni index `("index", …)` op'unda ve `IF NOT EXISTS`
- [ ] Net index deltası rapora yazıldı (G042'nin düşürdüğü + bu görevin eklediği)
- [ ] `pytest` yeşil, test sayısı düşmedi
