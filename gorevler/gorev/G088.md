# G088 — Vite dev sunucusu localhost'a bağlanır (LAN vektörü kapanır)

- **Bant:** frontend
- **Bağımlı:** -
- **Dosya kapsamı:** frontend/vite.config.ts
- **Dokunma:** frontend/package.json (DOKUNMA — sürüm yükseltmesi G089'un işi),
  .claude/launch.json (izlenmeyen dosya, repo'ya girmez)

## Hedef

`frontend/vite.config.ts:9` şu an `host: "0.0.0.0"` — vite dev sunucusu tüm ağ
arayüzlerine bağlanıyor, yani aynı Wi-Fi'daki herkes erişebiliyor. Kurulu vite
5.4.19'da dört bilinen açık var (bkz. güvenlik denetimi 2026-08-22, B-1); ikisi
tam olarak Windows'a özgü (`server.fs.deny` bypass — high; launch-editor NTLMv2
hash sızması). Geliştirme Windows 11'de yapıldığı için bu kombinasyon gerçek.

Bu görev **tek satırlık azaltmadır**: LAN vektörünü kapatır. Açıkların kendisini
kapatmaz — onun için G089 (vite 6.4.3) şart. İkisi ayrı görev çünkü bu değişiklik
risksiz ve bugün alınabilir, yükseltme ise ayrı bir doğrulama turu ister.

```diff
   server: {
-    host: "0.0.0.0",
+    host: "127.0.0.1",
     port: 8000,
```

**Neden kırmıyor:** dev sunucusu host'ta koşuyor (`npm --prefix frontend run dev`),
konteynerde değil — `package.json` script'i `"dev": "vite"`, `--host` bayrağı yok.
Docker frontend'i ayrı bir nginx imajı (`frontend/Dockerfile:28`), vite kullanmıyor.
Yani başka bir makineden dev sunucusuna erişim ihtiyacı bulunmuyor.

## Kabul kriterleri

- [ ] `frontend/vite.config.ts` içinde `host: "127.0.0.1"`; `0.0.0.0` string'i
      dosyada KALMADI
- [ ] `port: 8000` ve `strictPort: true` değişmedi; `proxy` bloğu aynen duruyor
      (uçlar: `/api`, `/process`, `/confirm`, `/preview-email-body`,
      `/preview-client-email-body`, `/refresh`)
- [ ] Değişikliğin yanına kısa bir şerh yazıldı: neden localhost (LAN vektörü +
      G089 atfı), yoksa bir sonraki kişi "uzaktan test edeyim" diye geri alır
- [ ] `package.json` ve `package-lock.json` DEĞİŞMEDİ (yükseltme G089'un işi)
- [ ] Testler + lint + tip kapısı yeşil
