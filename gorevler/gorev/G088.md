# G088 — Vite dev sunucusu localhost'a bağlanır (LAN vektörü kapanır)

- **Bant:** frontend
- **Bağımlı:** -
- **Dosya kapsamı:** frontend/vite.config.ts
- **Dokunma:** frontend/package.json (DOKUNMA — sürüm yükseltmesi G089'un işi),
  .claude/launch.json (izlenmeyen dosya, repo'ya girmez)

## Hedef

`frontend/vite.config.ts:9` şu an `host: "0.0.0.0"` — vite dev sunucusu tüm ağ
arayüzlerine bağlanıyor, yani aynı Wi-Fi'daki herkes erişebiliyor. Kurulu vite
5.4.19'da dört bilinen açık var (bkz. güvenlik denetimi 2026-08-22, B-1); ikisi
tam olarak Windows'a özgü (`server.fs.deny` bypass — high; launch-editor NTLMv2
hash sızması). Geliştirme Windows 11'de yapıldığı için bu kombinasyon gerçek.

Bu görev **tek satırlık azaltmadır**: LAN vektörünü kapatır. Açıkların kendisini
kapatmaz — onun için G089 (vite 6.4.3) şart. İkisi ayrı görev çünkü bu değişiklik
risksiz ve bugün alınabilir, yükseltme ise ayrı bir doğrulama turu ister.

```diff
   server: {
-    host: "0.0.0.0",
+    host: "127.0.0.1",
     port: 8000,
```

**Neden kırmıyor:** dev sunucusu host'ta koşuyor (`npm --prefix frontend run dev`),
konteynerde değil — `package.json` script'i `"dev": "vite"`, `--host` bayrağı yok.
Docker frontend'i ayrı bir nginx imajı (`frontend/Dockerfile:28`), vite kullanmıyor.
Yani başka bir makineden dev sunucusuna erişim ihtiyacı bulunmuyor.

## Kabul kriterleri

- [x] `frontend/vite.config.ts` içinde `host: "127.0.0.1"`; `0.0.0.0` string'i
      dosyada KALMADI
- [x] `port: 8000` ve `strictPort: true` değişmedi; `proxy` bloğu aynen duruyor
      (uçlar: `/api`, `/process`, `/confirm`, `/preview-email-body`,
      `/preview-client-email-body`, `/refresh`)
- [x] Değişikliğin yanına kısa bir şerh yazıldı: neden localhost (LAN vektörü +
      G089 atfı), yoksa bir sonraki kişi "uzaktan test edeyim" diye geri alır
- [x] `package.json` ve `package-lock.json` DEĞİŞMEDİ (yükseltme G089'un işi)
- [x] Testler + lint + tip kapısı yeşil

## Doğrulama

- `npm --prefix frontend test`
- `npm --prefix frontend run lint`
- `npx --prefix frontend tsc -b --force frontend`

## Rapor

DURUM: TAMAM

### Yapılanlar

- `frontend/vite.config.ts`: `server.host` `"0.0.0.0"` → `"127.0.0.1"`. Yanına
  7 satırlık şerh: neden loopback (LAN vektörü), Windows'a özgü iki açık,
  açıkların asıl kapanma yeri G089, ve geri almak yerine tek seferlik
  `npm run dev -- --host` bayrağı kullanılması gerektiği. Şerh "GERİ ALMA"
  ifadesiyle başlıyor — kabul kriterindeki "bir sonraki kişi geri alır"
  riskine doğrudan cevap.
- Yeni nöbetçi test: `frontend/src/config/devServerBind.test.ts` (4 test).
  Dört şeyi bağlar: host'un `127.0.0.1` olduğu, wildcard bind string'inin
  dosyada hiç geçmediği, `port: 8000` + `strictPort: true`'nun durduğu ve
  proxy allowlist'indeki altı ucun eksilmediği.

### Alınan kararlar + gerekçeleri

- **Şerhte wildcard adres literal olarak yazılmadı** ("Tüm-arayüz bindi
  (wildcard adres)" denildi). İlk taslakta şerh `"0.0.0.0"`u tırnak içinde
  örnek olarak veriyordu; bu, kabul kriterindeki "`0.0.0.0` string'i dosyada
  KALMADI" maddesini ve nöbetçi testin `not.toContain` iddiasını ihlal
  ediyordu. Anlam kaybı yok, kriter net kazanıldı.
- **Nöbetçi test kaynak METNİ okuyor, config'i import etmiyor.** `vite.config.ts`
  `lovable-tagger` gibi dev eklentileri yüklüyor; `vitest.config.ts` zaten bu
  yüzden ayrı bir config olarak duruyor (dosyadaki şerh). Test dosyası
  `import.meta.url`'den göreli çözümle okuyor, cwd'ye bağımlı değil.
- **Test `src/config/` altına kondu**: `vitest.config.ts` `include` deseni
  `src/**/*.test.{ts,tsx}` — kök dizindeki bir test dosyası sessizce
  toplanmazdı.
- `package.json` / `package-lock.json`'a dokunulmadı; vite yükseltmesi G089.

### İzlenecekler

- **NOT:** Nöbetçi testin kırmızı-yeşilini mekanik olarak gösteremedim: config'i
  geçici olarak wildcard bind'e döndürme denemesi izin sınıflandırıcısınca
  engellendi (`Edit frontend/vite.config.ts` → `host: "0.0.0.0"`, "Blocked by
  classifier"). Engel yerinde bir engel, zorlanmadı. Kırmızılık yapı gereği
  kesin: iki iddia (`/host:\s*"127\.0\.0\.1"/` eşleşmesi ve
  `not.toContain("0.0.0.0")`) değişiklik öncesi dosyada ikisi birden düşer.
- Bu görev açıkları KAPATMAZ, yalnız erişim vektörünü daraltır. Vite 5.4.19'daki
  dört açık G089 (vite 6.4.3) alınana kadar duruyor.
- `npm ci` çıktısı hâlâ "2 vulnerabilities (1 moderate, 1 high)" diyor — beklenen,
  G089'un konusu.
