# G011 — Denetim: outbox 'uploaded' + belge URL yazımı atomik/self-heal

- **Bant:** backend
- **Bağımlı:** -
- **Dosya kapsamı:** backend/services/upload_queue.py, backend/services/document_pipeline.py (yalnız `_record_upload_result` çevresi), backend/tests/** (upload outbox test dosyası)
- **Dokunma:** backend/models.py (şema değişikliği GEREKMEMELİ; gerekirse BLOKE bırak), backend/api.py, backend/services/export_publisher.py (notify tetiği YER DEĞİŞTİRMEZ)

## Hedef

Denetim bulgusu (dar çift-arıza penceresi): `upload_queue.py` outbox satırını "uploaded"
COMMIT ettikten SONRA `document_pipeline._record_upload_result` belgeye
`sharepoint_url` + `upload_status='uploaded'` yazarken DB hatasıyla düşerse, belge
süresiz "pending + URL'süz" kalıyor ve bunun retry yolu yok (outbox artık pending değil;
yalnız ERROR loglanıyor, `document_pipeline.py:275`). Pencereyi kapat:

**Tercih edilen yol:** iki yazımı TEK DB transaction'da birleştir (aynı Session'da outbox
statüsü + belge alanları, tek commit) — pencere yapısal olarak yok olur.
**Mimari engel çıkarsa** (session sahipliği ayrıştırılamıyorsa): self-heal reconcile —
mevcut startup reconcile taramasını "outbox uploaded AMA belge URL'süz" durumunu yakalayıp
`_record_upload_result`'ı yeniden deneyecek şekilde genişlet. Hangi yolu seçtiğini ve
nedenini Rapor'a yaz.

Değişmezler: hukukbot notify SADECE belge URL'si commit edildikten sonra tetiklenir
(mevcut sıra korunur); zehirli-dosya bekçisi (deneme sayacı upload'dan önce commit)
bozulmaz; log sözleşmesi (deneme WARNING, kalıcı arıza TEK ERROR) korunur.

## Rapor

**Seçilen yol: TEK TRANSACTION (tercih edilen yol).** Self-heal reconcile
REDDEDİLDİ, gerekçesi mimari değil veri: başarı anında spool dosyası siliniyor
ve `upload_outbox` satırında webUrl'i tutan bir kolon YOK (`models.py:576-599`).
Yani "uploaded ama belgesi URL'süz" bir satır yakalansa bile reconcile'ın elinde
ne yeniden yükleyecek payload ne de yazacak URL kalıyor — kurtarma verisi
hayatta kalmıyor. Session sahipliği ise ayrıştırılabilirdi: `_attempt_upload`
sonuç-yazma session'ını zaten kendisi açıyor, `_record_upload_result`'a
devretmek yetti.

### Yapılanlar

1. `document_pipeline._record_upload_result(doc_id, web_url, db=None)` — iki mod:
   - `db=None` (klasik): eskisi gibi kendi session'ını açar, commit eder,
     DB hatasını yutup False döner (fallback `async_islenmis_upload` + outbox'ın
     BAŞARISIZ-deneme yolu bunu kullanmayı sürdürür; oralarda satır zaten pending
     kaldığı için atomikliğe gerek yok).
   - `db` verili (yeni): yazım çağıranın açık transaction'ına katılır;
     commit/rollback/close çağırana ait, DB hatası YUKARI FIRLAR.
   - `✅ SharePoint URL updated` INFO'su yalnız commit'i kendi atan modda kalır —
     atomik modda commit'ten önce "yazıldı" loglamak yanıltıcı olurdu; o bilgi
     artık commit'ten SONRA outbox'ın "yüklendi" INFO satırına ek olarak düşer.
2. `upload_queue._record_doc_attempt(..., db=None)` → `_record_upload_result`'a
   iletir.
3. `upload_queue._attempt_upload` başarı yolu: `row.status='uploaded'` +
   `_record_doc_attempt(..., db=db)` **sonra tek `db.commit()`**. Pencere
   yapısal olarak yok oldu. Değişmezler korundu: notify_hukukbot yine commit'ten
   SONRA ve yalnız `url_saved` ise; deneme sayacı hâlâ upload'dan ÖNCE ayrı
   session'da commit ediliyor (zehirli-dosya bekçisi); spool silme hâlâ durum
   commit'inden sonra.

### Alınan kararlar + gerekçe

- **Hata artık yutulmuyor, fırlatılıyor (atomik modda).** İstisna
  `_attempt_upload`'ın mevcut `except`'ine düşüyor → `db.rollback()` ikisini
  birden geri sarıyor → satır `pending` + `next_attempt_at` NULL kalıyor, bir
  sonraki `_scan_once` yeniden deniyor (SharePoint'e ikinci kopya overwrite,
  zararsız). Bu yol WARNING üretiyor (retry edilebilir), eski ERROR
  (`document_pipeline.py:275`) bu yolda artık yok — log sözleşmesine daha uygun,
  ERROR-oranı alarmını çalmıyor.
- **`_record_upload_result` imzası genişletildi, kopyalanmadı.** Belge alanlarını
  upload_queue içinde ikinci kez yazmak (kopya mantık) sözleşmenin iki yerde
  ayrışmasına yol açardı.
- **Crash penceresi kanıtı:** iki yazımın ARASINDA artık hiç commit yok. Süreç o
  aralıkta ölürse transaction hiç commit edilmemiş olur → PostgreSQL bağlantıyı
  düşürdüğünde ikisi de geri sarılır; satır `pending` kalır, açılış reconcile'ı
  (`_scan_once` ilk taraması) devralır. `test_..._commit_failure_leaves_no_half_
  written_state` bunu commit'in kendisini patlatarak kanıtlıyor: kalıcılaşan ara
  durum (journal) BOŞ.

### Testler

`backend/tests/test_faz3_upload_outbox.py`: transaction semantiğini gerçekten
taklit eden `_TxSession` eklendi (commit → izlenen nesnelerin hali "kalıcı"
olur, rollback son kalıcı hale geri sarar, `journal` her commit'te
(satır statüsü, belge URL'si) çiftini tutar). Mevcut `_FakeSession` yalnız
commit/rollback sayıyor, Python nesnesindeki mutasyonu geri almıyor — "satır
pending'e döndü mü" sorusunu cevaplayamıyordu.

- `test_attempt_success_writes_row_and_document_in_one_transaction` — 'uploaded'
  ile URL aynı commit'te; journal'da "uploaded ama URL'süz" kalıcı durum yok;
  hook o commit'ten sonra açılıyor.
- `test_attempt_success_doc_write_failure_rolls_back_outbox_row` — belge
  yazımına DB hatası enjekte: satır `pending`e geri sarılıyor (`done_at` None),
  belge dokunulmamış, `attempts=1` korunuyor (bekçi), spool duruyor,
  `_is_due` True (yeniden denenir), 1 WARNING / 0 ERROR (kök logger dahil).
- `test_attempt_success_commit_failure_leaves_no_half_written_state` — crash
  penceresi; journal boş.
- Mevcut testlerdeki `_record_upload_result` sahteleri yeni imzaya uyarlandı;
  başarı testi artık `db is not None` bekçisi taşıyor (atomik bağlantı imza
  değişirse test düşer).
