# G225 — Kurumsal avukat kimliği `AVK-00001` + silme kapanır (yalnız pasif) + bağlar kilitlenir

- **Bant:** backend
- **Bağımlı:** G224
- **Dosya kapsamı:** `backend/models.py` (`Lawyer.kimlik`), `backend/database.py::_MIGRATIONS` (kolon + doldurma + AYRI unique index op + FK değişikliği), `backend/managers/reference_lists.py` (lawyers silme/güncelleme davranışı), `backend/routes/config.py` (lawyers DELETE/PUT), `backend/schemas.py` (gerekirse), `backend/scripts/avukat_yazim.py` (yeni kayda kimlik), `backend/scripts/import_lawyers_excel.py` (yeni kayda kimlik), testler
- **Dokunma:** diğer referans listelerin silme davranışı (DEĞİŞMEZ — testle), `frontend/**`

## Hedef
Kullanıcı kararı 27.09: avukat kimliği KURUMSAL olur — `AVK-00001` biçiminde, sistem üretir, kullanıcıya gösterilmez,
bir kez verilir, değişmez, yeniden kullanılmaz, her ortamda (prod/lokal/yedek/Hukukbot) aynıdır. Veritabanının `id`'si
yalnız tablolar arası FK olarak içeride kalır; sistemler arası ve API'de kimlik `kimlik` alanıdır.
Güvence (kullanıcı onaylı): avukat kaydı ASLA silinmez. Bugün `reference_lists.delete_item` kaydı `db.delete` ile
siler ve "clear" modu kartlardaki avukat alanını BOŞALTIR; `case_lawyers.lawyer_id` `ON DELETE SET NULL` — üçü de dava
kaybı yolu.

## Kabul kriterleri
- [ ] `lawyers.kimlik VARCHAR(9)`: migrasyon kolonu ekler, mevcut satırları deterministik sırayla (`sequence`, sonra `id`) `AVK-00001`… doldurur (yalnız boş olanlar — idempotent), AYRI `("index", ...)` op ile `UNIQUE` + (Postgres'te) `NOT NULL` + biçim `CHECK (kimlik ~ '^AVK-[0-9]{5}$')`. Koşullu op tuzağı (CLAUDE.md) testle bekçilenir: `create_all` önceden koşmuş DB'de de unique index var.
- [ ] Üretim: yeni avukat eklenince sunucu bir sonraki numarayı verir (en büyük + 1, unique ihlalinde yeniden dener); silinmiş/pasif kişinin numarası tekrar verilmez (en büyük üzerinden sayıldığı için); `kimlik` hiçbir güncelleme yolunda değişmez (PUT gövdesinde gelse yok sayılır ya da 422 — seçim rapora).
- [ ] Silme: `lawyers` için DELETE (özel uç ve genel `/api/config/delete`) kaydı SİLMEZ, `active=false` yapar; "clear" ve "keep" modları lawyers için REDDEDİLİR (422, Türkçe mesaj); "reassign" istenirse kartlar hedef avukata taşınır ama kaynak kayıt yine silinmez, pasif olur. Diğer listelerin davranışı değişmez.
- [ ] FK: `case_lawyers.lawyer_id` kısıtı `ON DELETE RESTRICT`'e çevrilir (Postgres: idempotent DROP/ADD CONSTRAINT op; sqlite testinde model tanımı); kaydı ham SQL ile silme girişimi hata verir (test).
- [ ] Pasif avukatlar: config listesi ve menüler (`get_lawyers`) mevcut `active` davranışını korur; pasif avukatın eski kartları filtrede hâlâ bulunur (test: pasif avukat seçilebilir mi — mevcut davranış neyse korunur, rapora).
- [ ] Envanter kapısı: lokal DB'de G224 fotoğrafı ÖNCE alınır, migrasyon + testler sonrası `--karsilastir` İHLAL 0 (çıktı rapora).
- [ ] Doküman: `docs/mimari/dava-acma-akisi.md` avukat kaydı bölümü (kimlik biçimi, silinmezlik).

**Kararlar**
- PUT/update gövdesinde gelen `kimlik` **yok sayılır** (422 değil): `kimlik` hiçbir `editable` listesinde yok,
  eski istemciler kırılmaz; ORM bekçisi betik yollarını da kapatır.
- Kimlik API çıktısına (`LIST_REGISTRY.fields`) EKLENMEDİ: alanlar Excel dışa aktarımına da gider ("kullanıcıya
  gösterilmez"), API sözleşmesi G227/G228'in işi.
- Üretim ORM `before_insert`/`before_flush` otomatiğiyle DEĞİL, açık çağrıyla: G224'ün mevcut testi ORM ile
  doğrudan kurulan avukatta `kimlik: None` bekliyor (test değiştirilmez); Postgres NOT NULL kimliksiz yeni yolu
  sessiz kalmadan durdurur.
- `block` modu avukatta kullanım sayısına bakmadan pasife alır: pasife almak veri kaybettirmez; 409 akışı artık
  gereksiz ("Sil" → "Pasife al" G229).
- Kimlik çakışması tespiti Postgres'te SQLSTATE 23505 + kısıt adı (`db_errors` kuralı); SQLite SQLSTATE taşımadığı
  için orada mesajdaki `lawyers.kimlik`.
- Doldurma `ORDER BY sequence, id` (NULL sequence en sona — Postgres ASC varsayılanı).

**Pasif avukat seçilebilir mi (mevcut davranış korundu):** `get_lawyers`/config listesi yalnız aktifleri verir →
pasif avukat menüden SEÇİLEMEZ; adıyla gelen filtre (`_lawyer_filter_case_ids`) önbellekte bulamayınca
toleranslı ad eşlemesine düşer ve eski kartları aynen bulur (test: pasife almadan önce/sonra aynı küme).
