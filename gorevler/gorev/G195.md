## Hedef
Karar 020 modeli — `cases.status` yalnız DERDEST | DANIŞ | MAHZEN, temyiz/istinaf/karar AŞAMADIR
(`cases.case_stage` + `case_stage_decisions`, dava detayı "Takip" sekmesi) — bugün yalnız uygulama
kodunda (`constants.normalize_case_status`) korunuyor; script ya da elle SQL `status='TEMYIZ'`
yazabilir. Veritabanı düzeyinde kapat:
`ALTER TABLE cases ADD CONSTRAINT ck_cases_status_uclu CHECK (status IN (<CASE_STATUSES>)) NOT VALID` —
idempotent (`DO $$ … IF NOT EXISTS (pg_constraint) …`), ayrı koşulsuz `("index", ...)` op'u (G041 kuralı).
`NOT VALID` mevcut satırları denetlemez → migrasyon prod'da bozuk eski değere TAKILMAZ; yeni INSERT/UPDATE'i
zorlar. `VALIDATE CONSTRAINT` bu görevde YOK — G183 `perf_olcum` prod'da üçlü dışı = 0 gösterince ayrı görev.
Değer listesi `constants.CASE_STATUSES`'ten üretilir (elle yazılmaz).
