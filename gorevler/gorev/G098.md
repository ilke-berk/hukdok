## Hedef

2026-08-22 bildirim denetiminin üç "düşük" frontend kalemi (#7, #8). Hiçbiri
bugün kullanıcıya hata olarak yansımıyor; üçü de aynı iki dosyada.

### (a) `loadList()` state updater'ının içinde (bulgu #7)

`NotificationBell.tsx` `zileTiklandi`: `setOpen((onceki) => { if (!onceki)
void loadList(); return !onceki; })`. React updater'ları **saf** olmalı — React
bunları eager hesap + render'da yeniden çağırabilir; yan etki mükerrer istek
üretebilir. 2026-08-22'de canlıda programatik tıklamayla **tek** istek ölçüldü
(bugün mükerrer YOK), yani bu bir davranış düzeltmesi değil hijyen: yan etki
updater dışına çıkar (`if (!open) void loadList(); setOpen(!open)` ya da
`useEffect([open])`). Kapalıyken açılınca listenin yeniden çekilmesi
davranışı AYNEN korunur (mevcut test bunu kilitliyorsa referans ver).

### (b) `markRead` hatası sessiz (bulgu #8)

`useNotifications.markRead`: POST `ok` değilse hiçbir şey olmuyor — kullanıcı
tıkladı, satır okunmuş görünmedi, neden bilmiyor. Toast DEĞİL (toast seli
riski, G002 dersi): panel içinde satır düzeyinde kısa bir "işaretlenemedi"
durumu (mevcut `listError` deseniyle aynı üslup), bir sonraki başarılı
işlemde ya da panel kapanınca temizlenir. `markAllRead` için de aynı.

### (c) 401 / `null` yanıt yolu testsiz (bulgu #8)

`useAuthRequest` istisnada `null` döner; hook bunu sessiz geçiyor (sayaç
korunur — doğru davranış) ama **testi yok**. İki test:
- `authRequest` null → `unreadCount` DEĞİŞMEZ (son bilinen değer kalır)
- `authRequest` null → `loadList` `listError` dolar, `items` boşalır
