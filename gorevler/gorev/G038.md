### Sonraki oturum için keşifler (yeniden keşfedilmesin)

1. **`tests/` imaja GİRMİYOR** (`backend/.dockerignore:29-35` — 2,7 MB test paketi bilerek
   dışlanmış). Görev dosyasındaki "imajdan tek-seferlik konteyner kaldır" kısıtı tek başına
   YETMEZ: konteyner içinde koşacak test kodu yoktur. Kapsam içi tek çözüm test kodunu
   çalışma ağacından **salt-okunur** mount etmek (`-v "$PWD/backend:/app:ro"`): kütüphane
   ortamı yeni imajdan, test kodu `git pull`'un getirdiği ağaçtan gelir — ikisi de aynı
   commit'tir. `.dockerignore`'a dokunmak dosya kapsamı dışında.
2. **`docker compose run` alternatif DEĞİL — prod DB riski taşır.** Compose servisi olarak
   koşmak `.env`'i (gerçek `DATABASE_URL` + SharePoint/Gemini sırları), default + `hukuk_shared`
   ağlarını ve `backend-data` volume'unu beraberinde getirir. `tests/conftest.py:25-27`
   `DATABASE_URL`'i `setdefault` ile koyar → env'de gerçek URL varsa **korunur**, ve
   `tests/test_migration_path.py` (dbtest) ulaşabildiği Postgres'te scratch veritabanı
   **yaratıp düşürür**. Yani compose yolu prod postgres'e DDL koşturabilir. Temiz env'li
   `docker run` bu yüzden şart.
3. `--entrypoint bash` zorunlu: imajın ENTRYPOINT'i `docker-entrypoint.sh` (migrate + uvicorn).
4. `--user root` gerekir: imaj `USER appuser` ile biter (`backend/Dockerfile:39`), dev
   bağımlılıkları `/usr/local/lib`'e kurulacak.
5. pip erişimsizliğini test başarısızlığından ayırmanın yolu konteyner içi özel çıkış kodu:
   `pip install … || exit 91` → 91 = uyar ve **atla** (deploy durmaz), diğer non-zero = **dur**.
6. Kapı `docker compose build` ile `docker compose up -d` arasına, `${BACKEND_IMG}:${NEW_SHA}`
   etiketlendikten sonra girer.

Denenmiş (koşulamamış) taslak — sonraki oturum buradan başlayabilir, ama **kanıtlanmadan
commit edilmemeli**:

```bash
GATE_SKIP_EXIT=91          # konteyner içi: pip erişimi yok → kapı atlanır, deploy DURMAZ

test_gate() {
    local img="$1" t0=$SECONDS rc=0
    if [ "${SKIP_TESTS:-0}" = "1" ]; then
        say "════════════════════════════════════════════════════════════"
        say "  ⚠️  SKIP_TESTS=1 — TEST KAPISI ATLANDI (bilinçli)"
        say "  Prod'a test edilmemiş kod çıkıyor."
        say "════════════════════════════════════════════════════════════"
        return 0
    fi
    say "🧪 Test kapısı: ${img} (tek seferlik konteyner, çalışan stack'e dokunulmaz)..."
    docker run --rm --entrypoint bash --user root \
        -v "${PWD}/backend:/app:ro" -w /app \
        -e PYTHONDONTWRITEBYTECODE=1 -e HOME=/tmp \
        "$img" -c "pip install --no-cache-dir -r requirements-dev.txt || exit ${GATE_SKIP_EXIT}
                   python -m pytest -p no:cacheprovider" || rc=$?
    local dt=$((SECONDS - t0))
    [ "$rc" -eq 0 ] && { ok "Test kapısı GEÇTİ (${dt} sn)"; return 0; }
    [ "$rc" -eq "$GATE_SKIP_EXIT" ] && {
        say "⚠️  Test kapısı ATLANDI: dev bağımlılıkları kurulamadı (pip ağ erişimi yok?)."
        say "    Kod TEST EDİLMEDEN deploy ediliyor — kapı bilerek durdurmuyor (${dt} sn)."
        return 0
    }
    fail "❌ Test kapısı KALDI (çıkış ${rc}, ${dt} sn) — deploy DURDU, çalışan stack'e
dokunulmadı. Bilinçli atlamak için: SKIP_TESTS=1 ./deploy.sh"
}
```

Kuru koşuyu deploy akışından bağımsız kanıtlanabilir kılmak için `--gate-only` argümanı
(script başında, `git pull`'dan ÖNCE dönen bir dal) düşünüldü; kabul kriterindeki
"çıkış kodu görüldü" kanıtı en temiz böyle üretilir.
