- **Bant:** backend (ana dizin; nginx + bekçi + token doğrulayıcı)
- **Bağımlı:** G284
- **Dosya kapsamı:** `nginx.conf` (yalnız üç `add_header Content-Security-Policy` kopyası `:48-51` ve iki location'daki
  tekrarları + `location = /eklenti/manifest.xml` `Content-Type: application/xml`, `no-cache`), `backend/tests/test_nginx_eklenti.py`
  (YENİ: üç CSP kopyası AYNI, Office.js kaynakları içerir, manifest location var), `backend/auth_verifier.py` (YALNIZ ölçüm
  sonucu gerektirirse: `ALLOWED_AUDIENCES` listesi — varsayılan mevcut tek audience, davranış değişmez) + testi,
  `docs/mimari/kimlik-ve-token.md` (eklenti kimliği paragrafı — ölçüm sonucuyla), `.env.example`
- **Dokunma:** `nginx.conf` diğer location'lar (Hukukbot/Lexis blokları, `/api`, `/assets`), `frontend/**` (G287),
  `backend/routes/**`

Kaynak: plan §6.1 "Eklenti kimliği", §6.2 K16, §6.5 "Eklenti kimliği", "CSP". CLAUDE.md: `add_header` kalıtım tuzağı

## Hedef
`/eklenti` sayfası Word görev bölmesinde açılabilsin (CSP Office.js'e izin verir, manifest servis edilir) ve eklentinin
alacağı token HUKDOK backend'inde doğrulansın — ölçülerek.

## Kabul kriterleri
- [ ] CSP üç kopyada AYNI genişler: `script-src` += `https://appsforoffice.microsoft.com https://ajax.aspnetcdn.com`
      (Office.js ve bağımlıları — işçi Office.js'in güncel CDN listesini belgeden doğrular, rapora link), `connect-src` +=
      `https://login.microsoftonline.com` (MSAL — zaten varsa dokunma), `frame-ancestors` Word'ün görev bölmesi için
      `https://*.officeapps.live.com https://*.office.com` (yalnız `/eklenti` location'ında — ana sayfa `frame-ancestors`
      daraltılmış kalır; bu yüzden `/eklenti` için AYRI location + beş güvenlik başlığının tam kopyası).
- [ ] `location = /eklenti/manifest.xml` → `frontend/public/eklenti/manifest.xml` (Vite `public/` ile `dist/`e kopyalanır),
      `Content-Type application/xml`, `Cache-Control no-cache`; G287 dosyayı yazar, bu görevde yer tutucu manifest (geçerli
      XML iskeleti, `<Id>` GUID, `<SourceLocation>` `/eklenti`) konur.
- [ ] Bekçi `test_nginx_eklenti.py`: CSP kopyaları birbirine eşit (`/eklenti` kopyası yalnız `frame-ancestors`'ta farklı
      ve fark testte açıkça yazılı), manifest location var, `/eklenti` location'ında `add_header` beş başlığın tamamı.
- [ ] **Token audience ölçümü** (rapora): MSAL.js NAA ile Office eklentisi aynı Azure uygulama kaydından `api://<client>/
      access_as_user` scope'u alabilir mi? Belge kanıtı (Microsoft Learn NAA sayfası, tarih) + hangi ayar gerekir (uygulama
      kaydına `brokerRedirectUri` / "Mobile and desktop" platform `brk-multihub://<domain>`). Gerekiyorsa
      `ALLOWED_AUDIENCES` (virgüllü, varsayılan mevcut `api://<client>`) `auth_verifier`'a eklenir, test iki audience ile;
      Azure uygulama kaydı değişikliği **İNSAN ADIMI** olarak plan §6.5'e ve rapora yazılır.
- [ ] `docker compose build frontend && docker compose up -d frontend` → `nginx -t` temiz; `curl -sI
      http://127.0.0.1:8080/eklenti/manifest.xml` 200 + `application/xml`; `curl -sI http://127.0.0.1:8080/` CSP başlığı
      değişmemiş `frame-ancestors`.
- [ ] `docs/mimari/kimlik-ve-token.md`: "Word eklentisi kimliği" bölümü (ölçüm sonucu, gerekli Azure adımı).
