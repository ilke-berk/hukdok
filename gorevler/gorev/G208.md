## Hedef
Hukbot kendi Azure kaydını bırakır; HukuDok frontend'inin gönderdiği access token'ı HukuDok'un
`backend/auth_verifier.py` kuralıyla birebir doğrular. Böylece hem LexisBio hem Hanyaloğlu kullanıcıları girer.

## Kabul kriterleri
- [ ] Env: `ALLOWED_TENANTS` (virgüllü) + `HUKDOK_CLIENT_ID`. Eski `AZURE_TENANT_ID`/`AZURE_AUDIENCE`/`AZURE_CLIENT_ID` kalkar;
      eksik env'de mevcut gibi açılışta `RuntimeError`.
- [ ] Doğrulama: `tid` ∈ `ALLOWED_TENANTS` (değilse 401) → `login.microsoftonline.com/{tid}/discovery/v2.0/keys` JWKS (tid başına önbellekli) →
      RS256, `aud == api://<HUKDOK_CLIENT_ID>` (çıplak client id KABUL EDİLMEZ — ID token sızmasın), `iss` ∈ {v2.0, sts.windows.net v1} (tid'den),
      `exp` zorunlu, `scp` içinde `access_as_user`. Kimlik `oid` (yoksa 401 — `sub`'a düşme KALKAR: sub uygulamaya özgüdür, geçmişi böler).
- [ ] `DEV_AUTH_BYPASS` korunur ama `X-User-OID` yalnız bypass'ta okunur (HukuDok nginx başlığı zaten siler — G203).
- [ ] Kullanıcı satırına `email` (`preferred_username|upn|email` üçlü fallback — HukuDok'taki Azure upn tuzağı) ve `name` yazılır/güncellenir; eski `full_name="User"` kayıtları ilk girişte düzelir.
- [ ] CORS: aynı origin'den gelindiği için `CORSMiddleware` kalkar ya da `ALLOWED_ORIGINS` boşsa eklenmez.
- [ ] Compose: `frontend` servisi kalkar (host 3000 portu kapanır); `api` 127.0.0.1:8010 + `hukuk_shared` kalır; `api`'nin `.:/app` bind-mount'u prod'da kod-imaj ayrımını bozuyorsa rapora not (bu görevde değiştirme).
- [ ] `tests/test_auth.py` (kendi RSA anahtarıyla imzalanmış token + JWKS mock): geçerli token → oid; yabancı tid 401; çıplak client id aud 401; scope yok 401; v1 iss geçer; süresi dolmuş 401; oid yok 401.
- [ ] Mevcut `tests/test_hukdok_ingest.py` değişmeden yeşil.
- [ ] Geçmiş korunumu notu rapora: LexisBio kullanıcısının oid'si kiracı içinde uygulamadan bağımsız → eski `users.id` ile eşleşir; lokal DB'de bir kullanıcıyla kanıtlanır.
