# G192 — Düşük etkili backend kalemleri: offset tavanı, N+1'ler, outbox vade filtresi SQL'de, PK ikizi index'ler, `status` CHECK (NOT VALID)

- **Bant:** backend
- **Bağımlı:** G190,G191
- **Dosya kapsamı:** `backend/routes/cases.py` (offset `le`, ilişki döngüsü 391-405), `backend/routes/clients.py` (poliçe döngüsü 158-168), `backend/services/upload_queue.py` (`_scan_once` 494-500), `backend/models.py` (PK `index=True` kaldırma), `backend/database.py` (`_DUSURULECEK_INDEXLER` + yeni `("index", ...)` op: CHECK NOT VALID), ilgili testler
- **Dokunma:** `backend/managers/case_manager.py` (G190'da bitti), `constants.CASE_STATUSES` (kaynak, değişmez)

Kaynak: `docs/arsiv/performans-denetimi-2026-09-14.md` D8, D9, D10, D11, D15. D12 (json→jsonb)
ve D13/D14 bilinçli KAPSAM DIŞI (aciliyet yok / tek konteyner).

## Hedef
Beş küçük, birbirinden bağımsız düzeltme; hepsi davranışı koruyarak:
1. **D8** `routes/cases.py:90` `offset` Query parametresine tavan (`le=10000`) ve `limit`'e mevcut
   tavan doğrulanır; tavan aşımı 422. Keyset sayfalama KAPSAM DIŞI (arama modunda relevance
   sıralaması offset ister).
2. **D11** `routes/cases.py:391-405` ilişki başına `first()` → id listesi `in_()` tek sorgu + dict;
   `routes/clients.py:158-168` poliçe başına `original_filename` sorgusu → tek `in_()` sorgu.
   `case_manager.py:1857-1858` G190 alanı, DOKUNMA.
3. **D15** `upload_queue._scan_once`: `next_attempt_at IS NULL OR next_attempt_at <= now` SQL'e
   taşınır (parçalı index `idx_upload_outbox_pending (next_attempt_at) WHERE status='pending'`
   kullanılır); `_is_due` Python yardımcısı kalabilir ama sorgu zaten eler.
4. **D10** `models.py`'de PK kolonlarındaki `index=True` (20 tablo: alleged_faults, appeal_courts,
   currencies, medical_events, …) kaldırılır; oluşmuş `ix_<tablo>_id` adları
   `_DUSURULECEK_INDEXLER`'e (G042 deseni, `("index", ...)` op'u). `idx_case_docs_conversion_pending
   (id) WHERE pending` DOKUNULMAZ (parçalı, müşterisi var — doğrula, rapora).
5. **D9** `cases.status` için `ALTER TABLE cases ADD CONSTRAINT ck_cases_status_uclu CHECK (status
   IN ('DERDEST','DANIŞ','MAHZEN')) NOT VALID` — idempotent (`DO $$ … IF NOT EXISTS
   (pg_constraint) …`), ayrı `("index", ...)` op'u (G041 kuralı: koşulsuz op). `NOT VALID`
   mevcut satırları denetlemez, yeni yazımları zorlar → migrasyon prod'da bozuk eski değere
   TAKILMAZ; `VALIDATE CONSTRAINT` G183 ölçümü prod'da 0 ihlal gösterince ayrı görevde.
   Değer listesi `constants.CASE_STATUSES`'ten üretilir (elle yazılmaz).
