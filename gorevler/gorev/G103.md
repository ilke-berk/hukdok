## Hedef

Veri ekibinin 25.08 ölçümü (HUKDOK_BELGELEME_OLAYI_BULGUSU_2026-08-25.md): bağlı föylerin
~%14'ünde tazminatın kaynağı tıbbi olay değil **belgeleme olayı** (aydınlatma ihlali /
tıbbi kayıt eksikliği); 45 dosyada "kusur yok ama tazminat var" görünümü doğdu. Ayrıca aynı
olgu yargı kademesine göre rol değiştiriyor ("saptandı" ≠ "kazandırdı"). Kullanıcı kararı
(02.09): iki alan açılır, prensiplere en uygun yolla — kapalı liste mekanizmasının kopyası,
zorunluluk yok, tahmin yazılmaz.

Bu görev şema + backend yollarını kurar: `cases`e iki kolon, iki seed'li kapalı referans
listesi, config uçları, kart okuma/yazma yollarında eş davranış, liste filtresi parametresi.

## SÖZLEŞME (dondurulmuş — G105 ile ORTAK; değiştirilemez, sapma gerekiyorsa BLOKE bırak)

- Kolonlar: `cases.olay_turu` VARCHAR(100) NULL, `cases.hukumdeki_rol` VARCHAR(100) NULL.
  Ad denormalize taşınır (iddia_edilen_kusur ile aynı desen). NULL = "karar okunmadı" —
  meşru durumdur, backfill YOK.
- Liste 1 — `event_types` (Olay Türleri), model `EventType`, seed'li 3 değer:
  `TIBBI` → "Tıbbi Olay" · `BELGELEME` → "Belgeleme Olayı" · `KARMA` → "Tıbbi + Belgeleme".
  KARMA gerekçesi: ölçümün "yan gerekçe" sınıfında iki tür birlikte görülüyor; kart alanı
  tek slot olduğundan karma durum açık değerle taşınır, tahminle tekilleştirilmez.
- Liste 2 — `judgment_roles` (Hükümdeki Roller), model `JudgmentRole`, seed'li 4 değer:
  `TEK-GEREKCE` → "Tek Gerekçe" · `YAN-GEREKCE` → "Yan Gerekçe" ·
  `YALNIZ-SAPTAMA` → "Yalnız Saptama" · `REDDEDILMIS-IDDIA` → "Reddedilmiş İddia".
  Anlam: belgeleme olgusunun **güncel kademedeki** hükümde oynadığı rol (E-9/bayat hüküm
  kuralıyla uyumlu; kademe değişince değer düzeltme partisiyle güncellenir).
- Uçlar: `GET/POST/DELETE /api/config/event_types` ve `/api/config/judgment_roles`
  (alleged_faults kalıbının birebir kopyası, POST/DELETE admin).
- Liste filtresi: `get_cases(..., olay_turu: str = None)` — `file_type` kalıbıyla eşitlik
  filtresi; `routes/cases.py` liste ucuna aynı adla query param.

## Yapılacaklar

1. **Modeller:** `EventType` + `JudgmentRole` — `AppealingParty`nin birebir kopyası
   (code unique, name, active, sequence). `cases`e iki kolon (`models.py:133` tasnif
   bloğunun yanına, yorumuyla).
2. **Migration:** `database._MIGRATIONS`a iki kolon `("columns", ...)` op'u (mevcut tasnif
   kolonları sözlüğü `database.py:649` civarındaki desenle). Tablolar `create_all` ile
   doğar; kalıcı kısıt/index GEREKMİYOR (unique code model tanımında — appealing_parties
   emsali). G041 kuralı: kısıt eklemek gerekirse DAİMA ayrı `("index", ...)` op'u.
3. **Seed:** `seed_data.py`ya iki seed fonksiyonu, satır başına `_ekle_yarissiz`
   (G058 dersi — worker yarışı ERROR basmamalı). Kod ASCII ve değişmez kimlik.
   NOT: `alleged_faults` seed'lenmez (bilinçli, ellemeden bırak); bu iki liste seed'lenir
   çünkü değerleri karşı taraf teyidi beklemiyor — 25.08 belgesi + 02.09 kullanıcı kararı
   ile bizde sabitlendi.
4. **Referans listesi kaydı:** `reference_lists.py` LIST_REGISTRY + DEPENDENCIES
   (`event_types` → Case.olay_turu "dava", `judgment_roles` → Case.hukumdeki_rol "dava")
   + görünen ad haritası; `config_manager.py` cache alanları; `routes/config.py` uçları —
   hepsi alleged_faults satırlarının ikizi.
5. **Kart yolları — eş davranış kuralı:** `grep -rn "iddia_edilen_kusur" backend/`
   çıktısındaki her dosyada (hukdok_aktarim.py HARİÇ) iki yeni alan eş muamele görür:
   `schemas.py` (Optional[str], ~:394 bloğu), `case_manager.py` serializer(lar)ı
   (~:454), kart güncelleme yolu. Güncelleme yolunda kapalı liste doğrulaması G066
   deseniyle: değer listede yoksa RET (400'e çıkan yol), liste BOŞSA WARNING'le geç.
6. **Liste filtresi:** `get_cases`e `olay_turu` parametresi (case_manager.py:729
   file_type kalıbı) + route query param + `X-Total-Count` davranışı bozulmaz.
