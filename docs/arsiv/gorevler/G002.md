## SÖZLEŞME (dondurulmuş — G001 ile ortak, birebir uy)
```
{"status": "failed", "error_ozet": "<kullanıcıya gösterilecek Türkçe mesaj>", "error_kod": "<etiket>"}
```
- `error_kod`: `gemini_saturated` | `gemini_blocked` | `gemini_truncated` | `analysis_error`
  (+ ileride `schema_invalid`; frontend etikete göre davranış AYIRMAZ, yalnız `error_ozet`i
  gösterir — etiket telemetri/log içindir).
- `failed` SON olaydır; `process_id` taşımaz. Mevcut `{"status":"error","message"}` aynen kalır.
- `analyzeDocument.ts` StreamMessage tipine `failed` eklenir; hem `error` hem `failed`
  reddetmeyle biter — `failed` reddi kullanıcı-dostu `error_ozet` mesajını taşır.

## Rapor

### Yapılanlar
1. **Hata ≠ boş veri (hedef 1):**
   - `useCases.getCases`: hatalı/`null` yanıtta artık `{cases: [], total: 0}` DEĞİL,
     `CASE_LIST_ERROR` mesajlı Error fırlatıyor.
   - `useClients`: query hatada `CLIENT_LIST_ERROR` fırlatıyor; hook `isClientsError`,
     `clientsError`, `refetchClients`, `isRefetchingClients` dışa veriyor (react-query v5'te
     `isLoading` hata sonrası false'a düşer, spinner'da takılma yok).
   - Yeni ortak bileşen `frontend/src/components/system/DataErrorBanner.tsx`: "Sunucuya
     ulaşılamadı — liste yüklenemedi" + "kayıtlarınız silinmedi" güvencesi + Tekrar dene
     butonu (`role="alert"`).
   - Kullanım: `CaseList` (loadError state + banner; hata halinde "bulunamadı" boş görünümü
     render edilmiyor), `ClientList` (hata dalı boş-liste dalından önce), `AvukatDashboard`
     ve `IdariDashboard` (Promise.all/getCases try/catch + reloadKey ile tekrar dene).
2. **`getClientCaseSequence` fail-hard (hedef 2):** sessiz `1` fallback'i kaldırıldı; yanıt
   yok / !ok / gövde JSON değil / `sequence` sayı değil veya <1 → `CASE_SEQUENCE_ERROR`
   fırlatır. 4 çağrı noktası:
   - `NewCase.tsx` (~:318): catch → `sequenceError` bayrağı + toast; `handleSubmit` yeni
     kayıtta bayrak doluysa kaydı bloke ediyor; Ofis No kartının altında `role="alert"` mesaj.
   - `QuickCaseModal.tsx` (~:282): catch → toast + `return` (dava hiç açılmıyor).
   - `IntakeReviewStep.tsx` (:245 effect yolu): `regenerateTrackingSafely` sarmalayıcısı —
     hata `sequenceError`'a düşer, kaydet kapısı (`canCommit`) ve `handleSave` bloke, alanda
     uyarı metni; başarılı üretimde bayrak temizlenir.
   - `IntakeReviewStep.tsx` (:540 409-retry yolu): tekrar sırasında sequence yine alınamazsa
     bayrak kaldırılıyor ki sonraki denemeler de bloke olsun.
3. **`failed` terminal olayı (hedef 3):** `analyzeDocument.ts` StreamMessage'a
   `{status:"failed", error_ozet?, error_kod?}` eklendi; `AnalysisFailedError` (message =
   `error_ozet`, `code` = telemetri etiketi, davranış AYIRMAZ) fırlatılıyor. `failed` her
   konumda reddettirir — öncesinde `complete` gelmiş olsa bile veri dönmez, form varsayılan
   veriyle dolmaz. Eski `{status:"error"}` sözleşmesi aynen korunuyor (düz Error).

### Kararlar + gerekçeler
- **Index.tsx'e dokunulmadı (görev izni kullanıldı):** `handleAnalyze` catch'i zaten
  `error.message`'ı toast'lıyor ve `setAnalysisData` yalnız başarıda çağrılıyor → `failed`
  reddi kullanıcıya `error_ozet` olarak yansıyor, form dolmuyor. `preloadNextFile`'ın sessiz
  catch'i tasarım gereği (fırsatçı ön-yükleme; dosya sırası gelince gerçek analiz hatayı
  yüzeye çıkarır).
- **useClients'ta `retry: false`:** apiClient GET katmanı (Faz 4.1) zaten 3 deneme yapıyor;
  react-query'nin ek 3 denemesi hata şeridini ~7 sn geciktirirdi. Tekrar kullanıcıya bırakıldı.
- **Banner toast değil kalıcı şerit:** kaybolan toast "kayıt yok" görünümüyle yarışıyordu;
  şerit boş-liste görünümünün YERİNE geçiyor ve "kayıtlarınız silinmedi" güvencesini veriyor.
- **QuickCaseModal'da state bayrağı yok:** akış tek fonksiyonluk; catch içinde `return` kaydı
  zaten bloke ediyor, kalıcı bayrak gereksiz.
- **`AnalysisFailedError.code` gevşek tip (`string & {}`):** sözleşmedeki ileride
  `schema_invalid` gibi yeni etiketler frontend değişikliği gerektirmesin.
