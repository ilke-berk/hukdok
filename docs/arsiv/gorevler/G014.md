# G014 — Hata yutan kapılar: mükerrer dava tespiti + ofis no sıra tahsisi (backend ayağı)

- **Bant:** backend
- **Bağımlı:** -
- **Dosya kapsamı:** backend/managers/case_manager.py, backend/routes/cases.py, backend/tests/
- **Dokunma:** frontend/** (G019'un işi — backend sinyali önce oturmalı), backend/managers/case_manager.py içindeki `get_cases`/`search_cases` sorgu mantığı (FAZ E'nin işi, burada DOKUNULMAZ)

## Hedef

Plan FAZ 0.2 ve 0.4. İki kapı hata durumunda "sorun yok" sinyali üretiyor:

1. `case_manager.py:805-807` — `find_duplicate_cases` (tanım `:772`) istisnada
   `logger.error(...)` + `return []`. Çağıran `routes/cases.py:180-187`
   (`api_check_duplicate_case`) bunu `{"matches": []}` + HTTP 200 olarak döndürüyor.
   Sonuç: DB hatasında **mükerrer dava kapısı sessizce açılıyor** ve aynı esas no ikinci
   kez kaydedilebiliyor.
2. `routes/cases.py:168-170` — `get_client_case_sequence` (tanım `:123-124`) istisnada
   `return {"sequence": 1}`. Sabit 1, gerçek sıradan bağımsız; çakışma üretir.
   (Not: `:146`'daki `{"sequence": 1}` erken çıkışı **hata değil** — `client_name` boş,
   ona dokunma.)

İkisi de "hata ≠ boş veri" disiplinine geçmeli: istisna yutulmayacak, çağırana ayırt
edilebilir bir başarısızlık sinyali gidecek. Mevcut sözleşme referansı: `routes/cases.py:230-234`
yorumundaki G002 deseni ("Hata YUTMAZ") — aynı üslubu izle.

### Yapılanlar

1. **`managers/case_manager.py::find_duplicate_cases`** — `except Exception: logger.error(...)
   + return []` bloğu KALDIRILDI; `try/finally: db.close()` kaldı. İstisna çağırana
   (route'a) ulaşıyor. Docstring'e G014 gerekçesi yazıldı.
2. **`routes/cases.py::api_check_duplicate_case`** — manager çağrısı `try/except`e alındı;
   hata → TEK `logger.error(..., exc_info=True)` + `HTTPException(503)`. Başarı yolu
   aynen `{"matches": [...]}`.
3. **`routes/cases.py::get_client_case_sequence`** — `except`teki `return {"sequence": 1}`
   yerine `logger.error(..., exc_info=True)` + `HTTPException(503)`. `:146`'daki boş
   `client_name` erken çıkışı DEĞİŞMEDİ (test ile kilitlendi).
4. **`backend/tests/test_g014_error_gates.py`** (yeni, 6 test) — sahte `_BoomSession`
   (`query()` `OperationalError` fırlatır, `close()` izlenir) ile DB'siz doğrulama.

### Kararlar + gerekçeleri

- **Seçilen sözleşme: HTTP 503 + `{"detail": "..."}`** (kabul kriteri "5xx ya da ayırt
  edilebilir hata gövdesi" seçimi). Gerekçe: her iki arıza da geçici bağımlılık (DB)
  arızasıdır, kod hatası değil — 503 bunu jenerik 500'den ayırır ve istemciye "tekrar
  dene" der. Gövde biçimi Faz 5-B doygunluk sözleşmesiyle (`/confirm` 503) aynı tutuldu;
  frontend `readErrorDetail` bu biçimi zaten işliyor, G019 ayrı bir gövde şeması
  öğrenmek zorunda kalmayacak.
- **ERROR nerede yazılıyor:** manager artık log YAZMIYOR, nihai ERROR route'ta. Log
  sözleşmesi (nihai başarısızlık TEK ERROR) korunuyor; çift log riski test ile kilitli
  (`test_check_duplicate_logs_single_error`).
- **`find_duplicate_cases` imzası değişmedi** (özel istisna tipi tanımlanmadı): tek çağıran
  route ve orada tüm istisnalar aynı sözleşmeye çevriliyor; yeni tip taşıma maliyeti
  karşılığında bir şey kazandırmıyordu.
- `get_cases`/`search_cases` sorgu mantığına (FAZ E) ve `frontend/**`e (G019) DOKUNULMADI.
